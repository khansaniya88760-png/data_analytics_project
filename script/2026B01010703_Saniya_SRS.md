## 2. Overall Description

### 2.1 Business Problem

An online shopping company receives orders from several cities, in five product categories, paid in four different ways. The manager does not know clearly which categories and cities bring the most revenue, whether slow delivery is hurting customer ratings, or whether big discounts really lead to bigger orders. This analysis will help the manager decide where to focus marketing, which payment options to promote and which cities need faster delivery.

### 2.2 Objectives

The project answers these four questions:

1. Which product category and which city bring the highest revenue and the highest average order value?
2. Which payment mode is used the most, and does it differ for New, Returning and Prime customers?
3. Do delivery time and discount percentage affect the customer rating?
4. How do the number of orders and the revenue change from month to month?

### 2.3 Intended Users

| User | What they need from this project |
|---|---|
| Operations manager | To know which city has slow deliveries and whether delay lowers the rating |
| Marketing manager | To know which categories and payment modes to promote and whether discounts work |
| Business head | To see monthly revenue trends and the best performing cities and categories |

### 2.4 Tools and Environment

| Tool | Version | Used for |
|---|---|---|
| Python | 3.12 | Programming language |
| pandas | 3.0 | Loading, cleaning and grouping data |
| NumPy | 2.5 | Calculations on numeric columns |
| Matplotlib / Seaborn | 3.11 / 0.13 | Charts |
| Jupyter Notebook / VS Code | Latest | Writing and running the notebook |
| GitHub | Not applicable | Storing and sharing the project |

### 2.5 Assumptions and Constraints

- The dataset is synthetic and was created with an AI tool.
- The dataset has 255 rows, so the results show patterns in this data only.
- A discount is valid only between 0 and 100 percent; any value outside this range is treated as an error.
- Order_ID is unique for each order, so rows that repeat the same order are treated as duplicates.
- Outliers in order value are real large orders, so they are flagged but not deleted.

### 3.2 Data Dictionary

| Column | Type | Valid values or range | Meaning |
|---|---|---|---|
| Order_ID | ID | Unique, format ORD#### | Identity of the order |
| Order_Date | Date | YYYY-MM-DD (2024-11-20 to 2026-11-11) | Date on which the order was placed |
| City | Category | Delhi, Mumbai, Bengaluru, Kolkata, Lucknow | City of the customer |
| Product_Category | Category | Beauty, Books, Electronics, Fashion, Home_Kitchen | Category of the products ordered |
| Payment_Mode | Category | UPI, Credit_Card, Debit_Card, Cash_on_Delivery | How the customer paid |
| Customer_Type | Category | New, Returning, Prime | Type of customer |
| Items_Count | Number | 1 to 8 | Number of items in the order |
| Order_Value_INR | Number | 132 to 30,137 | Total value of the order in rupees |
| Discount_Percent | Number | 0 to 100 | Discount given on the order, in percent |
| Delivery_Days | Number | 1 to 8 | Days taken to deliver the order |
| Browsing_Time_Min | Number | 2.1 to 42.6 | Minutes the customer browsed before ordering |
| Customer_Rating | Number | 1.0 to 5.0 | Outcome: customer satisfaction rating |

### 3.3 Data Quality Issues

Problems found in the first-look notebook:

| Column | Problem found | How many | How it will be fixed, and why |
|---|---|---|---|
| All columns | Duplicate rows | 5 | Remove them, because the same order counted twice would increase the revenue |
| City | Inconsistent text | 7 | Remove extra spaces and use the same capital letters, because Delhi, delhi and DELHI are the same city (12 spellings become 5 cities) |
| Order_Value_INR | Missing values | 5 | Fill with the median of the same product category, because the median is not affected by very large orders |
| Delivery_Days | Missing values | 6 | Fill with the median, because delivery days are whole numbers with a few extreme values |
| Browsing_Time_Min | Missing values | 4 | Fill with the median, because a few customers browse for a very long time |
| Customer_Type | Missing values | 5 | Fill with the label Unknown, because the type cannot be guessed correctly |
| Discount_Percent | Impossible values | 2 | Values -20 and 135 are outside 0 to 100; treat them as missing and fill with the median |
